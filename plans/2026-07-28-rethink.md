# 2026-07-28 — The rethink: one gripe, many parts, one inbox

> Status: **done** (shipped 2026-07-28 as 0.7.0 — see updates.md)
> Driver: Sal recorded a walkthrough, stopped, hit Record again — and the panel switched to a brand-new
> gripe, making part 1 look destroyed. Plus: "the whole folder flow sucks", "I need a full path in the
> prompt", "I should be able to draw while recording". This project is the linchpin of his operation:
> **recording rambles about AI-built apps and feeding them back into Claude Code is the core loop.**
> Everything below serves that loop.

## Decisions made with Sal (2026-07-28)

1. **Back-to-back:** stopping and re-recording appends a **new part to the same open gripe**. One
   folder, one report, one prompt. Only `done` closes a gripe.
2. **A gripe is a container:** notes and recordings mix in one gripe, interleaved chronologically.
3. **Record is the hero action.** Element/region/draw/page are the secondary row.
4. **Full rethink** — data model, resilience, whisper queue, panel layout, folder flow, live drawing.
5. **Folder flow reimagined as the inbox** (reverses part of decisions.md 2026-07-26, sanctioned by
   Sal): the one folder is a **global gripe inbox**, not "the repo you're in". Pick it once, type its
   absolute path once, and every prompt carries a full absolute path Claude Code can read from any
   repo. No per-project picking, ever.
6. Deferred: pause/resume (chose parts instead), landing-site update (explicitly "after").

## Known bugs this kills

- Record→Stop→Record minted a new session; part 1 vanished from view (`App.tsx` `stopRecording` →
  `recording:add`).
- Second Whisper pass silently skipped when one was in flight (`runWhisper`'s `whispering.current`
  guard, no queue).
- Recorder lived only in panel memory until Stop — closing the panel mid-ramble lost everything.

## 1. Data model (DB v2)

`DB_NAME` stays `bug-recorder` (frozen). `DB_VERSION` 1 → **2**. New store:

```ts
// db.ts STORE gains: recordings: 'recordings'
// keyPath 'id', index 'bySession' on 'sessionId'
```

New type in `types.ts`:

```ts
export interface Recording {
  id: string;
  sessionId: string;
  /** 1-based part number within the gripe; names the rec-NN folder. */
  index: number;
  createdAt: number; // = meta.startedAt
  state: 'recording' | 'done';
  /** Set when the panel died mid-recording and the chunks were reassembled. */
  interrupted?: boolean;
  /** MediaRecorder mime, needed to reassemble chunks. */
  mime: string;
  /** Count of persisted 1s chunk blobs (`<id>:chunk:<n>`, n from 1) while state is 'recording'. */
  chunks: number;
  meta: RecordingMeta;
}
```

`Session` **loses** `kind` and `recording`, **gains** `recCount: number` (source of the next part
index, like `noteCount`). `RecordingMeta` itself is unchanged (`written`/`rev` stay inside it — the
flush machinery keys off them).

**Blob keys** (unchanged scheme, new owner): `<recordingId>:frame:<n>`, `<recordingId>:video`, plus
new `<recordingId>:chunk:<n>`.

**Migration** (inside `onupgradeneeded`, same versionchange transaction): for every session with
`kind === 'recording'`: put `recordings` record `{ id: session.id, sessionId: session.id, index: 1,
createdAt: session.recording.startedAt, state: 'done', mime: 'video/webm', chunks: 0,
meta: session.recording }`, then rewrite the session with `kind`/`recording` deleted and
`recCount: 1`. Because `recording.id === old session.id`, every existing blob key still resolves.
Plain note sessions just gain `recCount: 0` (or rely on `?? 0` at read sites — set it explicitly).

New db helpers: `putRecording`, `getRecording`, `listRecordings(sessionId)` (sorted by `index`),
`deleteRecording(id)` (cascades frame blobs per `meta.frames`, `:video`, `:chunk:1..chunks`).
`deleteSession` cascades notes **and** recordings.

`PanelState` (in `App.tsx`) gains `recordings: Recording[]` (active session's, sorted by index);
`state:get` returns them.

## 2. Message protocol (`messages.ts` + `background/index.ts`)

Remove `recording:add`. Add:

| Message | Background behavior |
| --- | --- |
| `{ type: 'recording:start'; id: string; name: string; origin: string }` | Ensure an open active session (reuse the `ensureSession` shape: active non-closed session, else create named `name`/`origin`). Create `Recording` `{ id, sessionId, index: session.recCount + 1, createdAt: now, state: 'recording', mime: '', chunks: 0, meta: <empty> }`, bump `recCount`, set `ACTIVE_SESSION`, `setRecordingActive(true)`, broadcast. Return `{ sessionId, index }`. |
| `{ type: 'recording:progress'; id: string; meta: RecordingMeta; mime: string; chunks: number }` | `putRecording({ ...rec, meta, mime, chunks })`. **No broadcast** (fires ~every 2s). |
| `{ type: 'recording:finish'; id: string; meta: RecordingMeta }` | state `'done'`, `chunks: 0`, `setRecordingActive(false)`, broadcast. |
| `{ type: 'recording:discard'; id: string }` | `deleteRecording`; broadcast. (Used when getDisplayMedia was granted but start failed later.) |
| `{ type: 'recording:recover'; id: string }` | Read chunk blobs 1..`chunks`, `new Blob(parts, { type: mime })` → `<id>:video`, delete chunk blobs, `state: 'done'`, `interrupted: true`, `meta.written = false`, `meta.durationMs` = last frame `t` (fallback: keep whatever progress wrote), broadcast. |

Existing `recording:written` / `recording:frame:delete` / `recording:line:update` /
`recording:line:delete` / `recording:transcript` / `recording:reviewed` keep their shapes but operate
on the **recordings store** (message `id` = recording id). `recording:setActive` stays.
`session:rewrite` flips notes AND all the session's recordings to unwritten (rev bump).

An **empty meta** constant for `recording:start`: `{ startedAt: now, durationMs: 0, sampled: 0,
frames: [], transcript: [], events: [], videoFile: 'walkthrough.webm', written: false }`.

**Manifest**: 4th command `draw-live`, suggested key `Alt+Shift+D`, description
"Draw on the page while recording". Background command handler: query active tab,
`ensureContentScript`, `tellTab({ type: 'draw:toggle' })`. `ContentCommand` union gains
`{ type: 'draw:toggle' }`. Version → **0.7.0** (manifest + package.json).

## 3. Recorder resilience + parts (`sidepanel/recorder.ts`, `App.tsx` logic)

- `Recorder` constructor takes the recording `id` (minted by the panel, passed to
  `recording:start`); rename `sessionId` field → `id`, blob keys unchanged in shape.
- `ondataavailable`: keep in-memory `chunks.push` AND persist `blobs.set(`${id}:chunk:${n}`)`
  (n increments from 1). Track `chunkCount`.
- **Progress persistence**: throttled ≥1500ms — after each kept frame, each final transcript
  segment, and each 1s tick, send `recording:progress { id, meta: snapshot, mime, chunks }`.
  Snapshot = the exact object `finish()` would return, minus thinning, `written: false`.
- `finish()`: unchanged pipeline; after `<id>:video` is written, delete `:chunk:1..chunkCount`.
- **App `startRecording`**: `ensureMic` → active tab → scope → `id = crypto.randomUUID()` →
  `new Recorder(handlers, lang, scope, id)` → `await r.start()` (screen-share refusal: nothing was
  created, just toast) → **then** `send recording:start` (so a refusal leaves no dangling record) →
  `recorderRef = r`. Remove the separate `recording:setActive` (start sets it). If `r.start()`
  succeeded but `recording:start` throws, call `recording:discard`.
- **App `stopRecording`**: `recording:setActive false` → `meta = await r.stop()` →
  `send recording:finish { id, meta }` → refresh → enqueue Whisper. Record button is enabled again
  the moment `finish` returns — back-to-back is the whole point.
- **Recovery**: on state load, any recording with `state === 'recording'` whose id isn't the live
  `recorderRef`'s → `send recording:recover { id }` → refresh → enqueue Whisper for it. Toast:
  `recovered an interrupted part`.
- **Whisper queue**: replace `whispering.current` scalar guard with a FIFO (`string[]` ref +
  serial runner). Enqueue on finish and on recover; each completion sends `recording:transcript`,
  refreshes, and direct-flushes that recording by id (the late-landing path — flush effects only
  watch the active session). UI shows per-recording status: `queued` / `transcribing…`.
- **Flush**: effect watches active session's recordings; for each with `!meta.written`, serially
  run `flushRecording(session, recording)` (single `flushingRec` guard, loop inside).
- **`finish()` (done button)**: copy prompt first (user activation), wait out in-flight flushes,
  flush pending notes AND every unwritten recording of the target session, then `session:close`.
- **Zip export**: one zip for the whole gripe, mirroring the disk layout below.

## 6. Draw-while-recording + click ripples (`content/index.ts`, `content/ui.ts`)

- On `{ type: 'draw:toggle' }` while the content script's recording flag is on: toggle a **live ink
  layer** — full-viewport fixed canvas in the existing shadow root, `z` above everything,
  crosshair cursor, pointer events captured while active. Freehand strokes: `ACCENT`, round caps,
  ~4px (dpr-aware) — same look as capture-mode ink. Strokes persist (multi-stroke) until cleared.
- Keys while the layer is active: `Esc` or the hotkey exits, `c` clears all strokes.
- On each stroke end: `chrome.runtime.sendMessage({ type: 'recording:mark' })` — the drawn state
  becomes a forced, ★-marked keyframe (panel already listens for `recording:mark`).
- Hint chip (existing `.glass` style): `drawing — c clears · esc done`, top-center, drops low when
  the cursor rises (same rule as the aim hint).
- Teardown + clear when the recording ends (`{ type: 'recording', active: false }`) or on exit.
- Honest limit, documented in ui.md + report: drawing lives **in the tab** — it appears in the
  recording because it's on screen; it cannot draw over other apps or chrome:// pages.
- **Click ripples**: while recording and not drawing, every `pointerdown` spawns a brief accent
  ring (fixed div, `pointer-events: none`, expand ~28→64px, fade 350ms) in the shadow root — clicks
  become visible in the video and keyframes. No messages, no capture interference.
