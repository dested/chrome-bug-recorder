## ADDENDUM 2 (2026-07-29, later still): the timeline must survive an hour

Sal, with a real 10:18 recording on screen: "these videos could be an hour long. this ui is
terrible. i cannot go to market with this." Root cause: absolutely-positioned fixed-size frame
thumbs overlap into a card-deck smear at fit zoom, and duration-scaled voice pills shrink to
unreadable fragments. The rendering layer is wrong; the data/selection model stands.

**Timeline v2 rendering (the NLE answer):**

1. **Filmstrip frames lane.** No per-frame absolute thumbs. The track divides into fixed-width
   cells (~72px wide at track height); each cell renders the keyframe nearest the center of its
   time slice, `object-fit: cover`, edge to edge, zero gaps, zero overlap — at ANY duration and
   ANY zoom. Zooming in refines the slices until cells ≈ single keyframes. Click a cell = place
   playhead at that cell's time + select the frame it shows. Double-click = pin in monitor.
   ★ marks render as small ticks in a thin strip along the filmstrip's top edge at their exact
   x (they're instants, not cells).
2. **Voice clips are blocks first, text second.** width = dur×pxPerMs (min 2px, snug 1px gaps,
   squared corners). Text renders ONLY when the clip is ≥48px wide. Under-playhead clip gets the
   bright treatment; selection = accent outline as today.
3. **Playhead readout.** Directly under the monitor: the transcript line covering (or nearest
   before) the playhead, full-width, readable (--fs-md), with its mm:ss. Click it → inline edit
   (same commit path as clip editing). This is the primary way long transcripts get read and
   fixed — scrub with the ruler or filmstrip, read here, edit here.
4. **Selection is time-range-first.** Marquee and ruler range-select resolve to a TIME RANGE
   (+ lanes covered by the marquee's y): select every frame/line whose extent intersects —
   including frames not individually visible as cells at this zoom. The selection bar gains a
   range summary: `0:42–1:10 · N items · delete`.
5. **No dead well.** The tracks container hugs its two lanes; nothing reserves empty height.
6. Monitor/ruler/zoom/drag-move/rev-guards/seams: unchanged from v1.

## Why

The report is the product, and the report is only as good as what's in it. The card list lets you
edit one line at a time; sanitizing a five-minute ramble needs an editor: everything on one time
axis, scrub it, grab a junk stretch, delete it, drag a line to where it belongs. Users will spend
hours here — that's the point.

## 1. Dock shortcuts, labeled (content script)

Buttons in the recording dock read `draw (d)` / `click (d)` (toggled), `clear (c)`, `mark (m)`,
`stop (s)`. The keys are handled by the CONTENT SCRIPT (a window keydown listener installed while
the dock is open) — NEVER manifest commands; Chrome silently refuses to bind those.

- Active whenever `dockOn && phase === 'idle'` — with ink capturing or not.
- Guard: skip when any modifier is held, or the event target (composedPath) is an
  input/textarea/select/contenteditable — typing on the page must never trigger us.
- `d` → toggleLive, `c` → clearLive, `m` → mark (same flash as the button), `s` → stop.
- Consolidate with the existing `onLiveKey` (Esc + silent `c`) into ONE dock-scoped handler so
  clear can't fire twice. Esc keeps its current behavior (exit draw-capture only, swallowed).
- `.dock button.draw { min-width }` must fit `click (d)` so the row never shuffles.

## 2. Ink fades on its own (content script)

Strokes fade out slowly instead of demanding `clear`. One GLOBAL opacity for all live strokes:

- `INK_HOLD_MS = 3000`, `INK_FADE_MS = 4000`. Track `lastInkAt` = end of the most recent stroke
  activity (pointermove while drawing, and pointerup). Opacity = 1 until hold expires, then
  linear → 0 over the fade; at 0, drop `liveStrokes` entirely.
- Any new stroke (pointerdown that becomes a real stroke, or first move) resets `lastInkAt`, and
  EVERYTHING pops back to full opacity — old strokes included. That's the user's exact ask.
- While `liveDrawing`, opacity is pinned at 1.
- Implementation: `paintLive` applies `ctx.globalAlpha`; a rAF loop runs only while strokes exist
  and opacity < 1 territory is possible (start it when the hold expires is fine; a simple
  always-on-while-strokes-exist loop is also fine — it's one canvas repaint).
- `clear (c)` stays as the instant wipe.

## 5. The timeline (the redesign)

### The model: one axis, takes invisible

A gripe renders as ONE time axis. Each recording ("take" — the word never appears in UI) occupies
a span: spans are laid end to end in `createdAt` order, no gaps. A thin seam line (no label, no
number) marks where a new take begins. Notes land at their chronological position: taken during a
take → that local time; between takes → pinned at the boundary, in order. **The words "part",
"rec", "recording 1/2" never appear in the UI again.**

### Position override: `tl`

Moving an item = giving it an explicit position on the unified axis.

- `TranscriptSegment.tl?: number`, `RecordingFrame.tl?: number`, `Note.tl?: number` — ms on the
  gripe's unified axis; ABSENT means "computed from t / createdAt". Set only when a human moved it.
- New shared lib `src/lib/timeline.ts` (owned by agent B1, imported by UI and markdown):

```ts
export interface PartSpan { rec: Recording; start: number; end: number }
/** Spans laid end to end in createdAt order. end - start = max(durationMs, 1000). */
export function partSpans(recordings: Recording[]): PartSpan[];
export function totalMs(spans: PartSpan[]): number;
/** tl ?? span.start + t */
export function linePos(rec: Recording, seg: TranscriptSegment, spans: PartSpan[]): number;
export function framePos(rec: Recording, frame: RecordingFrame, spans: PartSpan[]): number;
/** tl ?? createdAt mapped into its containing span, else clamped to nearest boundary. */
export function notePos(note: Note, spans: PartSpan[], recordings: Recording[]): number;
```

### New messages (pinned — B1 implements, B2 calls)

```ts
// types.ts
export type TimelineRef =
  | { kind: 'frame'; recId: string; index: number }   // RecordingFrame.index (identity, stable)
  | { kind: 'line'; recId: string; index: number }    // array position in meta.transcript
  | { kind: 'note'; noteId: string };
export type TimelineMove = TimelineRef & { tl: number };

// messages.ts Request additions
| { type: 'timeline:move'; moves: TimelineMove[] }
| { type: 'timeline:delete'; items: TimelineRef[] }
```

Background handlers: group by record, one read-modify-write per recording/note. Deletes: lines
are positional — delete per-rec in DESCENDING index order; frames delete by identity `index`.
Both ops bump `meta.rev`, set `written: false` (notes too), broadcast `state:changed`. Existing
single-item messages stay (the dock and old paths use them).

### The component (B2): `src/sidepanel/Timeline.tsx`

Replaces the card list in App.tsx wholesale. Layout, top to bottom:

```
┌──────────────────────────────────────────────┐
│                 monitor                       │  keyframe at/just-before the playhead,
│        (image, letterboxed, dark)             │  full-bleed; note thumb when a note is selected
├──────────────────────────────────────────────┤
│ 0:00      0:30      1:00      1:30    ▲ruler │  click = place playhead · drag = range select
├──────────────────────────────────────────────┤
│ frames  ▪  ▪ ▪   ▪     ▪  ▪                  │  thumbnails anchored at framePos
│ voice   [~~~clip~~][~clip~]  [~~~~clip~~~~]  │  segments: x=pos, w=duration (est. if no d)
│ notes      ◆         ◆                       │  markers at notePos
└──────────────────────────────────────────────┘
  [selection bar, only when selection ≠ ∅]:  N selected · [delete]
  [zoom: – ─────────── +]  fit-width default
```

- **Scrub**: dragging the playhead updates the monitor live (nearest frame ≤ playhead — image
  lookup, instant, no video seek). Clips under the playhead highlight.
- **Select**: click = single; ctrl/cmd-click = add; drag on empty track space = marquee
  multi-select; drag on the RULER = range select ("section") — selects everything inside, the
  selection bar's `delete` is the "delete section" the user asked for.
- **Move**: drag any selected clip horizontally → all selected move together → on drop, ONE
  `timeline:move` with every moved item's new `tl`. Escape cancels the drag.
- **Edit**: transcript clip → click when already selected (or double-click) opens inline text
  edit (existing `recording:line:update`). Note marker → same for its text (`note:update`).
  Frame → double-click expands it in the monitor.
- **Delete**: the selection bar's `delete` button → one `timeline:delete`. Delete/Backspace does
  the same, silently — unadvertised, the button is the path.
- **Review nag**: the "read this back" banner moves above the timeline (any take with transcript
  && !reviewed && not transcribing); `looks right` per pending take, same messages as today.
- **Whisper status**: App passes `busy: Record<string, string>` (recId → label); a quiet line
  above the tracks shows it while present.
- **Zoom**: default fit-to-width; `–`/`+` buttons (×1.5 steps) + ctrl-scroll on the tracks
  (silent bonus). Horizontal scroll when zoomed in.
- **Seams**: 1px dashed vertical line at each take boundary. No label.
- **Marks**: ★ tint on marked frames' thumbs.
- **Empty state**: unchanged copy ("nothing yet / hit Record…").
- **Narrow (380px)**: same component, tighter tokens — smaller thumbs, monitor shorter,
  selection bar wraps. It must stay fully functional; the pop-out is comfort, not a requirement.
- Visual language: ui.md tokens only, accent = state (selection/playhead/marks), no shadows.
  Track rows dark like AE (slightly deeper than --bg is allowed via one new token).
- Playing the actual webm in the monitor (per-take `<video>`, pause at take end) is a STRETCH —
  only if it lands clean; scrub-by-frames is the requirement.

### The report follows the axis (B1: markdown.ts)

`buildReport` drops the "## Part N — walkthrough" framing and emits ONE chronological flow
ordered by `linePos`/`framePos`/`notePos` (moves and deletes thus directly shape the report —
that's the sanitizing loop):

- Head: title, preamble (reword "part" → "the walkthrough"; a **take** boundary needs no prose),
  folder line, merged When/App line, `**Video:** rec-01/walkthrough.webm (3:12) · rec-02/…`,
  contact sheets block (all takes' grids, in axis order), console/network rollup (kept, with
  per-take drop counts merged).
- Body: a sequence of `##` blocks in axis order — note sections exactly as today; spoken windows
  as `## m:ss — "first words…"` (global axis mm:ss), same frame-rationing rules as today, frame
  paths keep their `rec-NN/` prefix (disk layout unchanged, invisible in prose).
- `transcript.txt`, `recording.json`, MANIFEST, zip layout, `agentPrompt`: unchanged.
